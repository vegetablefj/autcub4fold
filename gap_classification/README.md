# GAP classification computations

This directory separates reusable GAP functions from individual computation
modules.

## Shared functions

[`gap_functions.g`](gap_functions.g) supplies finite-group, character,
linear-conjugacy, invariant-cubic, and centralizer functions. Batch drivers
and functions tied to a particular record format remain in their module.

[`gap_functions.md`](gap_functions.md) records the interfaces, source
versions, dimension conventions, and regression checks for future changes.

## Computation directories

- [`gap_liftable_abelian/`](gap_liftable_abelian/README.md): the unchanged diagonal core, its wrapper, and 53 saved candidates.
- [`gap_nonliftable_abelian/`](gap_nonliftable_abelian/README.md): two theoretically classified actions, supplied as exact data.
- [`gap_small_nonabelian/`](gap_small_nonabelian/README.md): multiplier audit and complete current non-abelian target enumeration, including liftable but non-F-liftable actions; 182 candidates survive the prime-order restriction. The audit proves that no additional non-liftable branch is needed for these targets.
- [`gap_large_group_enumeration/`](gap_large_group_enumeration/README.md): representation calculations producing explicit rank-at-least-15 equation candidates, with task inputs and their saved correspondence to the large-family catalogue.
- [`gap_smoothness/`](gap_smoothness/README.md): smooth-member verification and family-wide singularity certificates.
- [`gap_saturation/`](gap_saturation/README.md): unified candidates and the completed equal-dimensional reduction from 177 smooth records to 156 representatives.
- [`gap_uniformization/`](gap_uniformization/README.md): fixed symplectic coordinates and simpler extra generators.
- [`gap_coordinate_presentation/`](gap_coordinate_presentation/README.md): exact correspondence between the computed groups and the canonical presentations.
- [`gap_manuscript_validation/`](gap_manuscript_validation/README.md): the final ordered matrix-and-basis catalogue, display checks, and exact coordinate witnesses.
- [`gap_self_conjugacy/`](gap_self_conjugacy/README.md): conjugate-family checks and separately recorded theoretical exemptions.
- [`gap_liftability/`](gap_liftability/README.md): liftability and F-liftability of the canonical fourfold catalogue.
- [`gap_threefold/`](gap_threefold/README.md): extraction of 40 threefold families by removing a Fermat summand.
- [`gap_fourfold_cross_dimension/`](gap_fourfold_cross_dimension/README.md): the completed cross-dimensional containment relation, its explicit matrices, covers, and action-maximal rows.

Each module guide distinguishes executable sources, generated reports, saved
machine-readable data, and purely theoretical input. A successful verification
of supplied candidates does not by itself prove that candidate generation was
exhaustive. Generated reports should be regenerated by their documented entry
point rather than edited by hand.

Run commands from the directory specified by the module. The two enumeration
wrappers require their own module directory. Most later drivers also support
the repository root, from which shared functions can be loaded by

```gap
Read("gap_classification/gap_functions.g");
```

The final program-readable matrix catalogue is
[`gap_family_catalogue.g`](gap_manuscript_validation/gap_family_catalogue.g).
The fixed representatives used by the earlier coordinate and containment
searches are supplied in
[`fourfold_search_catalogue.g`](gap_fourfold_cross_dimension/input/fourfold_search_catalogue.g).
[`../gap_result/`](../gap_result/README.md) presents the completed results;
it is not a program-input directory.
[`export_results.g`](export_results.g) regenerates those display files from
the completed module results, without repeating mathematical computations.
The ordered group names used only in that display are saved in
[`result_display_labels.g`](result_display_labels.g).
Literature and software references are collected in
[`../REFERENCES.md`](../REFERENCES.md), and the recorded software split is in
[`../ENVIRONMENT.md`](../ENVIRONMENT.md). Source keys and candidate numbers
are local to each stage unless a correspondence is explicitly supplied.
