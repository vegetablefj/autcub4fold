# Integral-action computations for the 156 families

This document gives the mathematical workflow and the saved sources.
The family numbers follow `../input/family_numbering.md`. Paths
below are relative to the repository root unless otherwise indicated.

The earlier source table groups the selected representatives into 36
earlier-search outputs, 18 supplementary classified-pair or No. 105 records, 43
same-symplectic-part restrictions, 53 changed-part restrictions, and six
action-maximal records. These are disjoint construction categories, not
counts of the separate proof arguments. The direct-source manifest gives
the exact saved record and selector used for each row.
The 18 supplementary rows are Nos. 1–11, 15, 16, 19, 20, 34, 42,
and 105. The first 17 complete a previously classified pair under a
prescribed extra action; No. 105 instead uses an exhaustive rank-ten
`T`-action and fitting-extension search on the identified No. 97 pair.

For a changed symplectic subgroup, the new invariant lattice is computed
from that subgroup's action on the same `Lambda0`. Restricting only the old
`T` action would lose the new `S`, the primitive embedding, and its gluing.
For a same-part restriction, the power is taken on `Lambda0` before its
actions on `S` and `T` are recorded. The order of this ambient matrix can
exceed the order of its Hodge character.

## Identification and scope

An unlabelled integral representative is enough for the numbered lattice
catalogue. A complete set of labelled matrices for every geometric
automorphism is needed only when a particular restriction uses those labels.
The source certificates record the extra information actually used:
primitive embeddings for `M10`, acted-on negative eigensublattices for
`L2(7):2`, full-group component types for `S3,3`, and an entire primitive
Hodge-character coset for `A3,3`. A single abstract group ID or a single
trace is insufficient in the ambiguous rows.

The subgroup search is exhaustive **inside the selected full parent**.
When one eligible parent-conjugacy class remains, the known geometric
containment identifies the child's unlabelled action. When several remain,
the case-specific certificate supplies the extra equivalence or selection.
No. 102 uses the identified No. 69 parent; its two No. 67 alternatives
have not been compared by an integral-conjugacy certificate. This does not
affect the No. 69 restriction used for the numbered representative.

Each stage retains its own root, stability, saturation, or group checks.
The direct-source batch receipt repeats structural consistency checks on all
156 saved ambient rows; it does not rerun every mathematical classification.
Consequently the stage certificates and geometric identification arguments
remain part of the proof, alongside the final catalogue.

For the algebraic step, let `P` be the very general period lattice and
`K = P^perp` in the primitive lattice `Lambda0`. The helper reconstructs
the odd unimodular full `H4` as an index-three overlattice of
`<h^2> + Lambda0`, where `(h^2)^2 = 3`. It computes
`A_gen = P^perp` in `H4`, the primitive closure of `<h^2> + K`.
The closure index is one or three; the complementary closure of
`<h^2> + P` has the other index. The script checks the determinant
identities and records Gram matrices for `P`, `K`, and `A_gen`. The completed
156-row export writes the split index-one cases as `A_gen = <3> ⊕ K` and
prints the `A_gen` matrix for index-three cases; all matrices remain in the
enriched MRDI. The saved MRDI passed a semantic reload check.

## Reproduction order

Use the frozen search outputs and stage-specific saved records as inputs to
each later step. The current 156-row file is
[`assembly/lattice_156_from_sources_standard.mrdi`](assembly/lattice_156_from_sources_standard.mrdi).
The [manifest](assembly/manifest.jl) fixes each source and selector; the
[earlier source table](ambient_completion/sources/family_156_sources_current.md)
retains detailed geometric citations and qualifications for the preceding
standard catalogue. The [assembly guide](assembly/README.md) gives commands
for rebuilding, structural verification, and algebraic enrichment.

Several historical build scripts have fixed output names or refuse to
replace saved evidence. To repeat them, use fresh output paths and the
required inputs. Exact-character or extension enumeration is needed only
when auditing a source result itself; direct assembly uses the saved results.
The completed [algebraic MRDI](assembly/lattice_156_with_algebraic.mrdi)
enriches the standard file, with a [text export](assembly/lattice_156_gram_matrices.txt)
in numbered order.
